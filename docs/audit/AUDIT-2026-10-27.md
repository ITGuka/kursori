## 1. Executive Summary

ტექნიკურად საიტი საშუალოზე მაღალ დონეზეა. Framework-ის უსაფრთხოება გააზრებულია: CSRF, HTMLPurifier, upload-ის MIME whitelist, uploads-ში PHP-ის აკრძალვა, login throttling და `composer audit`-ში 0 advisory. SEO-ს ბაზაც სუფთაა: hreflang+x-default, canonical, sitemap alternates-ით, FAQPage/BlogPosting, WebP `<picture>` და srcset. Desktop-ის Lighthouse Performance არის 97–99 🧪.

**3 მთავარი რისკი:**
1. **კონტენტი გამოგონილია.** ქეისები გამოგონილი მეტრიკებით ("60%", "3-ჯერ"), შეფასებები სახელებითა და კომპანიებით, გუნდის სახელები და stock ფოტოები ნამდვილად გამოიყურება. ეს იურიდიული და რეპუტაციული რისკია.
2. **ანალიტიკისთვის consent-ის ინფრასტრუქტურა არ არსებობს.** `head_code` ნედლად ისმება, ამიტომ GA4-ის დამატება პირდაპირ დაარღვევს Privacy Policy-ის საკუთარ დაპირებას და GDPR-ს.
3. **Deploy-ის flag-ები და indexing toggle გარემოს არ ითვალისწინებს.** ამჟამად ლოკალი ინდექსირებადია.

**3 მთავარი შესაძლებლობა:**
1. რეალური ქეისები (სკრინშოტები, live ბმული, შედეგი). სტუდიისთვის ეს ყველაზე ძლიერი trust და SEO აქტივია.
2. Bootstrap/jQuery/Owl/FA CDN სტეკის ჩანაცვლება self-hosted, მინიმალური bundle-ით. ეს mobile LCP-ს 6.2s-დან ~2.5s-მდე ჩამოიყვანს და CSP-სა და GDPR-ს ერთად მოაგვარებს.
3. `core/`-ში Consent Mode v2-ის და SEO-ს გარემოზე დამოკიდებული დაცვა. ეს მომავალ პროექტებზეც გადავა.

**Deploy-ისთვის მზადყოფნა:** საიტი **ჯერ მზად არ არის**. ბლოკერებია CNT-01 (demo/გამოგონილი კონტენტი), SEC-01 (`APP_ENV`/`APP_DEBUG`) და ANL-01 (consent, თუ ანალიტიკა გაშვების დღეს ემატება). კოდის დონეზე სხვა კრიტიკული ბლოკერი არ არის.

## 7. Solution Architect-ისთვის

### `core/`-ში გადასაწყვეტი (ყველა მომავალ პროექტზე გადავა)
1. **Environment guard:** ერთი `app()->isProduction()`. მასზე მიბმული: SEO indexable (SEO-01), analytics loader (ANL-01), debug-ის აკრძალვა (SEC-01), admin-ის ბანერი "არასწორი კონფიგურაცია".
2. **Consent მოდული:** `Core\Consent` (cookie-ის სქემა, Consent Mode v2-ის default/update, `<dialog>` banner partial, `consent_allows('analytics')` helper). `head_code` გადაიყოს კატეგორიებად: `necessary` / `analytics` / `marketing`, თითოეული `<script type="text/plain" data-consent="analytics">` pattern-ით.
3. **CSP nonce:** `Core\Http\Csp` middleware: ყოველ მოთხოვნაზე nonce, `csp_nonce()` helper view-ებისთვის, `report-uri` ლოგში. დამოკიდებულია self-hosted assets-ზე.
4. **Session/ქეში სტრატეგია:** lazy session, CSRF-ის double-submit cookie, page cache + `ETag`/`304`, bfcache-თან თავსებადი header-ები (PERF-02). Trusted proxies (SEC-05).
5. **SEO მოდული:** `Core\Seo\Meta` + `Core\Seo\Schema` (Organization/LocalBusiness, WebSite, BreadcrumbList, Article, FAQ, CreativeWork) + `/llms.txt` + per-page noindex/canonical + SERP preview admin-ში.
6. **Image pipeline (კარგად არის):** WebP+srcset+`<picture>` უკვე მუშაობს (`app/helpers.php:100-137`, `core/Media/ImageResizer.php`). PHP `imageavif` ხელმისაწვდომია, ამიტომ AVIF შეიძლება დაემატოს `<source type="image/avif">`-ად. Alt-ის სავალდებულობის რეჟიმი admin-ში.
7. **Front asset baseline:** Kursori-ის ნაცვლად framework-ის საკუთარი მინიმალური base (tokens.css + ~5KB vanilla JS: nav, reveal, dialog), რომელზეც შაბლონები ჯდება. ეს PERF-01 და DS-01 ყველა პროექტზე ერთხელ ხსნის.

### `app/`-ში (ამ პროექტისთვის)
კონტენტი (CNT-01), ბრენდი (UX-02), ფორმების notify (UX-01), heading/landmark-ების გასწორება (A11Y-02/04), ქეისის შაბლონი (UX-03).

### რისკები და ღია კითხვები
- სამიზნე აუდიტორია და ძირითადი კონვერსია ბრიფში შევსებული არ იყო. ახლა სამი არხია (კონტაქტი, შეთავაზება, ონლაინ შეკვეთა): რომელია **მთავარი**? ერთი ძირითადი CTA კონვერსიას გაზრდის.
- სად იქნება ჰოსტინგი (cPanel, Cloudflare)? ამაზეა დამოკიდებული SEC-04, SEC-05, brotli და HTTP/2.
- D7 გადაწყვეტილება (ფორმები email-ის გარეშე): მიზეზი? თუ spam-ის შიში იყო, honeypot და rate limit უკვე არის.
- ბრენდი dark-only არის შეგნებული არჩევანი?
- რეალური ქეისების რაოდენობა და კლიენტების თანხმობა: ეს განსაზღვრავს deploy-ის თარიღს.
